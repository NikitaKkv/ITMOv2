## 1. Исследование механизма копирования в буфер обмена (Clipboard API & Fallback)

### Контекст
Пользователю необходимо скопировать отформатированный текстовый отчет о результатах игры в один клик. В некоторых окружениях (небезопасный контекст HTTP без localhost, старые мобильные браузеры, строгие политики permissions) метод `navigator.clipboard.writeText` может выбросить исключение `NotAllowedError` или быть недоступен (`undefined`).

### Решение
Реализовать двухуровневый асинхронный механизм в `copyTextToClipboard(text)`:
1. Попытка вызвать современный стандарт `navigator.clipboard.writeText(text)` при наличии `navigator.clipboard`.
2. В случае ошибки или отсутствия API: безопасный fallback через скрытый временный элемент `<textarea>` с атрибутом `readonly`, вызовом `document.execCommand('copy')` и последующим немедленным удалением элемента из DOM.
3. Если оба метода завершились неудачей, функция возвращает `{ success: false, error: "CLIPBOARD_DENIED" }`, а UI активирует статус ошибки и автоматически выделяет текст в окне предпросмотра, чтобы пользователь мог нажать `Ctrl+C` (`Cmd+C`).

### Обоснование
- 100% покрытие браузеров, включая мобильные платформы.
- Мягкая деградация UX: пользователь никогда не оказывается в тупике, даже если браузер заблокировал прямой доступ к буферу.
- Соответствует требованиям `specs/contract.md` (раздел 5.1).

### Рассмотренные альтернативы
- *Использование сторонней библиотеки (clipboard.js):* Отклонено из-за архитектурного инварианта Vanilla JS (ноль внешних зависимостей).
- *Только navigator.clipboard без fallback:* Отклонено, так как на устройствах со строгой политикой безопасности вызовет недиагностируемый сбой копирования.

## 2. Исследование клиентского формирования и скачивания файла

### Контекст
Требуется локально сохранить отчёт матча в формате `.json` без обращения к внешнему серверу (pure client-side).

### Решение
Использовать стандартный браузерный стек Blob URL:
1. Создать объект `Blob([content], { type: mimeType + ';charset=utf-8' })`.
2. Получить временную ссылку через `URL.createObjectURL(blob)`.
3. Создать программный элемент `<a download="filename">`, вызвать `.click()`.
4. В блоке `setTimeout(..., 100)` освободить память через `URL.revokeObjectURL(url)`.

### Обоснование
- Нулевые накладные расходы на сеть и сервер.
- Мгновенное инициирование загрузки (менее 50 мс).
- Имя файла генерируется с датой и временем: `wordbridge-match-YYYY-MM-DD-HHmmss.json`.

### Рассмотренные альтернативы
- *Data URI (`data:text/json;charset=utf-8,...`):* Отклонено для длинных строк из-за лимитов браузеров на длину URL и необходимости ручного url-encoding.
- *Отправка данных на Python HTTP сервер для отдачи `Content-Disposition`:* Отклонено, так как игра должна работать автономно без серверных эндпоинтов.

## 3. Исследование доступности и паттерна модального окна (WAI-ARIA Dialog)

### Контекст
Модальное окно должно соответствовать принципам доступности (a11y) и не ломать пользовательский опыт на десктопах и смартфонах.

### Решение
Реализовать канонический WAI-ARIA паттерн модального диалога:
1. Разметка: `<div id="export-modal" class="modal hidden" role="dialog" aria-modal="true" aria-labelledby="export-modal-title">`.
2. Фокус-менеджмент:
   - При открытии модалки сохранять ссылку на элемент, вызвавший открытие (`triggerElement`), и переводить фокус на первую кнопку действия (кнопка копирования).
   - При закрытии восстанавливать фокус на `triggerElement`.
3. Обработка клавиши `Escape`: глобальный слушатель `keydown` закрывает окно, если оно активно.
4. Закрытие по фону (backdrop): клик на внешнюю область (`target === modalContainer`) приводит к безопасному закрытию.
5. Блок статуса снабжается атрибутом `aria-live="polite"` для оповещения программ экранного доступа без прерывания речи.

### Обоснование
- Полное соответствие требованиям WCAG 2.1 AA.
- Чистая реализация на нативном JavaScript без тяжелых фреймворков.
- Удобство для пользователей, управляющих игрой с клавиатуры.

### Рассмотренные альтернативы
- *Использование нативного HTML5 тега `<dialog>`:* Отклонено из-за необходимости полифиллов стилизации бэкдропа и кросс-браузерных нюансов анимаций в кастомной неоновой теме.
- *Модальное окно без фокус-трапа и aria-атрибутов:* Отклонено, нарушает критерии приемки и требования доступности FR-012 / SC-003.

## 4. Исследование машины состояний UI и временных интервалов (State Transitions)

### Контекст
При нажатии на кнопки действий пользователь должен видеть четкую индикацию текущего состояния (загрузка, успех, ошибка), исключая многократные клики (spamming/debouncing).

### Решение
Реализовать 4-фазную машину состояний:
- `idle`: кнопки активны, текст статуса нейтральный.
- `loading`: кнопки действий получают атрибут `disabled`, отображается анимация спиннера/пульсации.
- `success`: отображается зеленая плашка с галочкой/эмодзи; запускается таймер `setTimeout` на 3000 мс для плавного возврата в `idle`.
- `error`: отображается предупреждающая плашка с описанием проблемы и кнопкой повтора; кнопки действий разблокируются.

### Обоснование
- Детерминированное поведение исключает состояние гонки.
- Автоматический сброс через 3 секунды позволяет пользователю выполнить второе действие (например, сначала скопировать, а затем скачать файл) без повторного открытия окна.

### Рассмотренные альтернативы
- *Мгновенное закрытие окна после копирования:* Отклонено, так как не оставляет времени прочитать подтверждение и лишает возможности скачать файл.
- *Отсутствие таймаута сброса успеха:* Отклонено, так как старый статус «Скопировано» сбивает с толку при желании совершить повторное действие.
