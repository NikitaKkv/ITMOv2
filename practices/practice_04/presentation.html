Запуск и верификация проекта CLI Commands
1. Локальный сервер игры (Vanilla JS + HTML5) localhost:8000 ↗
python3 -m http.server 8000 --directory src
2. Детерминированные проверки (Синтаксис JS + 8 TDD-тестов) scripts/check_all.sh
./scripts/check_all.sh
3. Прогон собственного MCP-сервера (4 сценария) Handshake, Tools/list, Success, Error
python3 scripts/test_mcp.py
Собственный MCP-сервер (JSON-RPC 2.0) scripts/mcp_server.py

Реализован инструмент validate_association_bridge на чистом Python без сторонних зависимостей. Принимает JSON через stdin и возвращает результат в stdout.

Прямой вызов через stdin/stdout (демонстрация протокола)
Успешный вызов (валидный мост):
echo '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"validate_association_bridge","arguments":{"start":"Чайник","target":"Чёрная дыра","chain":["Кипяток","Пар","Космос"]}}}' | python3 scripts/mcp_server.py
Обработка ошибки (повтор слова):
echo '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"validate_association_bridge","arguments":{"start":"Чайник","target":"Чёрная дыра","chain":["Кипяток","чайник","Космос"]}}}' | python3 scripts/mcp_server.py

Реализованный функционал Фичи A и B
Фича A: Построитель ассоциативного моста (Chain Builder)
Интерактивный ввод узлов между стартовым и целевым словом, счётчик длины моста, стек отмены хода (Undo), динамическая проверка дубликатов, автоматическое замыкание с Web Audio API аккордом.
Фича B: Режим дуэли (Hot-seat Duel & Showdown)
Режимы «Гонка» (одна пара на двоих) и «Вызов» (загадка оппоненту), скрытый экран смены игрока, финальный экран Showdown со сравнением путей и кнопками взаимного судейства.
Изоляция процесса: Фича B разрабатывалась в изолированном git worktree и прошла независимый аудит субагентом @explore перед merge.
Методология и автоматизация Скиллы и хуки
Скилл TDD (Test-Driven Development)
Реализован по методологии Red-Green-Refactor: запрет на написание кода до падающего теста, тестирование контрактов на границах («seams»). 8 тестов в tests/test_logic.py покрывают базовую логику.
Двухуровневая система хуков
• Агентский хук: .agents/hooks.json (событие PostToolUse запускает проверки сразу после редактирования файлов).
• Git-хук: .git/hooks/pre-commit (блокирует коммит при падении синтаксиса или тестов).
