# Нагрузочные проверки

## Инфраструктура тестов

- Цель: проверить FastAPI POST `/api/reviews` по правилам SEC-1, API-1, REL-1 и формату OUT-1 под нагрузкой MVP.
- Инструменты: Locust 2.x (master + 2 workers) как генератор нагрузки.
- Тестовые данные: JSON `{ "diff": "..." }`.
  - Валидные diff ≤ 20000 символов.
  - Пограничные длины: 19999, 20000, 20001.
  - Паттерны секретов (SEC-1): `ghp_[A-Za-z0-9]{36}`, `password=\S+`, PEM-блоки: `-----BEGIN PRIVATE KEY-----` … `-----END PRIVATE KEY-----`.
- Мок внешнего LLM: HTTP-сервис с параметризуемой задержкой.
  - Быстрый путь: 50–200 мс.
  - Медленный путь: 12–15 с (провоцирует таймаут 10 с по REL-1 → контролируемый 504).
- Наблюдаемое: статистика Locust (RPS, p50/p95), коды ответов; логи приложения содержат только `request_id`, длительность, статус (OBS-1).

```mermaid
flowchart LR
  A[Locust] --> B[FastAPI /api/reviews]
  B --> C{len(diff) <= 20000?}
  C -- "Нет" --> D[413 Payload Too Large]
  C -- "Да" --> E[SEC-1: mask [REDACTED]]
  E --> F{LLM <= 10s? (REL-1)}
  F -- "Нет" --> G[504 controlled]
  F -- "Да" --> H[OUT-1: summary, risks<=3, checks]
  H --> I[200 OK]
```

## Сценарии нагрузки

| Сценарий | Правило | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|---|
| Валидный поток (diff ≤ 20000) | REL-1, OUT-1 | 5 RPS, 10 минут | p95 ≤ 3 с; 0 5xx | Время ответа, доля ошибок, соответствие OUT-1 | Locust p95 ≤ 3s; HTTP 200; OUT-1: `summary`, `risks` ≤ 3, `checks` |
| Порог длины | API-1 | Серии 19999/20000/20001 | 200/200/413 | Корректность порога | Коды 200, 200, 413 |
| Маскирование секретов | SEC-1 | 1 RPS, 5 минут; инъекции `ghp_...`, `password=...`, PEM | 100% `[REDACTED]` | Маскирование до вызова LLM | Мок LLM видит `[REDACTED]`; логи без секретов |
| Таймаут LLM под нагрузкой | REL-1 | 5 RPS, 10 минут; 20% медленных | 100% медленных → 504 ≤ 11 с | Долю 504, время до 504 | HTTP 504 для медленных; быстрые — 200 |

Для MVP масштабные стресс-тесты (десятки–сотни RPS) откладываем: сервис синхронен, зависит от внешнего LLM и не использует очередь/кэш. Условия старта: средний трафик > 2 RPS, SLA p95 < 1 с, переход на асинхронную архитектуру и/или собственный LLM.
