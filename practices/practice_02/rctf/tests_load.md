# Нагрузочные проверки

## Инфраструктура тестов

- Цель: проверить FastAPI POST `/api/reviews` по правилам SEC-1, API-1, REL-1 и формату OUT-1 под нагрузкой MVP.
- Генератор нагрузки: Locust 2.x (master + 2 workers).
- Тестовые данные: JSON с полем `diff`.
  - Валидные diff ≤ 20000 символов (синтетика на основе TRAINING_PR.diff).
  - Пограничные длины: 19999, 20000, 20001.
  - Строки с секретами для SEC-1: `ghp_[A-Za-z0-9]{36}`, `password=\S+`, блоки PEM: `-----BEGIN PRIVATE KEY-----` ... `-----END PRIVATE KEY-----`.
- Мок внешнего LLM: HTTP-сервис с управляемой задержкой ответа:
  - Быстрый путь: 50–200 мс.
  - Медленный путь: 12–15 с (провоцирует срабатывание таймаута 10 с по REL-1 → контролируемый 504).
- Источники измерений:
  - Статистика Locust (RPS, p50/p95 latency, доля ошибок по кодам).
  - Метрики/логи приложения: `request_id`, длительность, статус (OBS-1: без содержания diff и промпта).

Mermaid-схема маршрута запроса и ограничений:

```mermaid
flowchart LR
  A[Locust client] --> B[FastAPI /api/reviews]
  B --> C{len(diff) <= 20000?}
  C -- "Нет" --> D[413 Payload Too Large]
  C -- "Да" --> E[SEC-1: mask secrets]
  E --> F{LLM <= 10s? (REL-1)}
  F -- "Нет" --> G[504 Gateway Timeout (контролируемый)]
  F -- "Да" --> H[OUT-1: summary, risks<=3, checks]
  H --> I[200 OK]
```

## Сценарии нагрузки

| Сценарий | Правило | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|---|
| Поток валидных запросов (diff ≤ 20000) | REL-1, OUT-1 | 5 RPS, 10 минут | p95 латентности ≤ 3 с; 0 ответов 5xx | Время ответа, доля ошибок, корректность OUT-1 | Locust: p95 ≤ 3s; HTTP 200; OUT-1 содержит `summary`, `risks` ≤ 3, `checks` |
| Пограничный размер diff | API-1 | Серии payload с длиной 19999, 20000, 20001 | 200 для ≤20000; 413 для >20000 | Корректность порога 20000 | Коды ответов: 200/200/413 |
| Инъекции секретов маскируются | SEC-1 | 1 RPS, 5 минут; в payload включаем `ghp_...`, `password=...`, PEM-блок | 100% маскирование секретов | Долю маскированных токенов до вызова LLM | В мок LLM уходит `[REDACTED]` вместо исходных значений; логи не содержат секреты |
| Таймаут LLM под нагрузкой | REL-1 | 5 RPS, 10 минут; 20% запросов уводим в 12–15 с задержку мока | 100% зависаний превращаются в 504 ≤ 11 с; 0 5xx | Время до 504, доля 504 в соответствии с долей медленных | HTTP 504 для медленных; быстрые — 200; распределение кодов ≈ 80%/20% |

Для MVP масштабные стресс-тесты (десятки–сотни RPS) откладываем: сервис синхронен, зависит от внешнего LLM и без очереди/кэша. Условия старта масштабного профилирования: средний трафик > 2 RPS, требование SLA p95 < 1 с, переход на асинхронную архитектуру и/или собственный LLM.
