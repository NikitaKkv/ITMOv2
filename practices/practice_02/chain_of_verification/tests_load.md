# Нагрузочные проверки (Chain of Verification)

| Сценарий | Правило | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|---|
| Поток валидных запросов | REL-1 | 5 RPS, 10 минут | p95 латентность ≤ 3 с; 0 ошибок 5xx/504 | Время ответа API, доля ошибок | Метрики приложения; статус-коды 2xx; p95 из APM |
| Пограничный размер входа | API-1 | Серии с длиной 19999, 20000, 20001 | 200 OK для ≤ 20000; 413 для > 20000 | Корректность порога длины | Коды ответов 200/413 |
| Инъекции секретов под нагрузкой | SEC-1 | 1 RPS, 5 минут; смешанные входы с секретами | 100% маскирование секретов до LLM | Долю маскированных секретов | В промпте к LLM вместо `ghp_\w+`, `password=\S+`, PEM — `[REDACTED]` |
| Таймаут внешнего LLM под нагрузкой | REL-1 | 3 RPS, 10 минут; провайдер отвечает >10 с (мок) | 504/контролируемая ошибка при >10 с; без падений | Отделение успешных и таймаутов | Коды 200 и 504; отсутствие 5xx; лог таймаута |

## Инструменты и инфраструктура

- Генератор нагрузки: locust.
- Цель: POST `/api/reviews` FastAPI-сервиса из учебного кейса.
- Данные: искусственные diff-строки заданной длины; набор кейсов с секретами:
  - токен GitHub: `ghp_ABCDEFG1234567890` (паттерн `ghp_\w+`);
  - параметры вида `password=secret123` (паттерн `password=\S+`);
  - фрагменты приватных ключей PEM: `-----BEGIN PRIVATE KEY----- ...`.
- Изоляция REL-1: для сценария таймаута используем мок LLM, который спит >10 секунд, чтобы воспроизвести срабатывание таймаута без внешних зависимостей.
- Метрики: собираем p95 времени ответа, долю 2xx/4xx/5xx/504, количество маскированных секретов (по наличию `[REDACTED]` в переданном в LLM промпте). Для SEC-1 используем тестовый транспорт/мок клиента LLM, фиксирующий финальный промпт.

## Схема

```mermaid
flowchart LR
  L[Locust Users] --> A[FastAPI /api/reviews]
  A --> M[Маскирование секретов (SEC-1)]
  M -->|diff ≤ 20000| C[Клиент LLM]
  A -.->|len(diff) > 20000| E[HTTP 413 (API-1)]
  C -->|≤10с| R[Ответ 200 с OUT-1]
  C -.->|>10с| T[Таймаут 10с → 504 (REL-1)]
```

## Примечание о масштабе нагрузок

Для MVP масштабные стресс-тесты (десятки-сотни RPS) откладываем: сервис синхронен, не включает очередь/кэш и ограничен внешним LLM. Условия старта масштабного профилирования: рост среднего трафика > 2 RPS, требования SLA p95 < 1 с, переход на асинхронную архитектуру и/или собственный LLM.

## Как использовали AI

- Для чего: уточнить сценарии под правила SEC-1, API-1, REL-1; добавить инструменты и схему.
- Источники: CASE.md, unit/integration-проверки Практики 1.
- Что проверили сами: наличие привязки к правилам, конкретных паттернов секретов, сценария REL-1 под нагрузкой, корректность Mermaid и сохранение текста об отсрочке стресс-тестов.
