# Нагрузочные проверки

## Инфраструктура тестов

- Цель: проверить FastAPI POST `/api/reviews` в части SEC-1, API-1, REL-1 и OUT-1 под реалистичной нагрузкой MVP.
- Инструменты: Locust 2.x (master + 2 workers).
- Тестовые данные: JSON `{ "diff": "..." }`.
  - Валидные диффы: длина ≤ 20000 символов.
  - Пограничные длины: 19999, 20000, 20001.
  - Паттерны секретов (SEC-1): `ghp_[A-Za-z0-9]{36}`, `password=\S+`, PEM-блок: `-----BEGIN PRIVATE KEY-----` … `-----END PRIVATE KEY-----`.
- Мок внешнего LLM: HTTP-сервис с настраиваемой задержкой ответа.
  - Быстрый путь: 50–200 мс.
  - Медленный путь: 12–15 с (провоцирует таймаут 10 с по REL-1 с контролируемым 504).
- Источники метрик: статистика Locust (RPS, p50/p95), коды ответов; логи приложения содержат только `request_id`, длительность и статус (OBS-1).

```mermaid
flowchart LR
  A[Locust clients] --> B[FastAPI /api/reviews]
  B --> C{len(diff) <= 20000?}
  C -- "Нет" --> D[413 Payload Too Large]
  C -- "Да" --> E[SEC-1: mask secrets]
  E --> F{LLM отвечает <= 10s? (REL-1)}
  F -- "Нет" --> G[504 Gateway Timeout (контролируемый)]
  F -- "Да" --> H[OUT-1: summary, risks<=3, checks]
  H --> I[200 OK]
```

| Таймаут LLM под нагрузкой | REL-1 | 5 RPS, 10 минут; 20% запросов — медленные | 100% медленных → 504 ≤ 11 с | Время до 504, доля 504 | Медленные → 504; быстрые → 200 |

Для MVP масштабные стресс-тесты (десятки–сотни RPS) откладываем: сервис синхронный, зависит от внешнего LLM и не использует очередь/кэш. Условия старта масштабного профилирования: средний трафик > 2 RPS, требование SLA p95 < 1 с, переход на асинхронную архитектуру и/или собственный LLM.
