# Использование AI: что сделали инструменты и что исправили мы

## Инструменты

| Инструмент | Роль |
|---|---|
| **Lovable** | макет и первичный экран: 5 состояний, shadcn/ui, тема, демо-переключатель |
| **Кодинг-агент (OpenCode)** | интеграция с n8n, валидация, состояния, тесты, mutation-check |
| **n8n + LLM** | классификация Issue и простановка лейбла (практика 7.2) |

## Примеры промптов

**Макет (Lovable):**
> Build an internal tool screen "Issue Classifier"... Add a small dev-only state switcher:
> Empty / Filled / Loading / Success / Error... Do NOT add authentication, database or Supabase.

**Правила для агента (`AGENTS.md`):**
> Переиспользуй компоненты из `src/components/ui` (shadcn/ui). Цвета и отступы — только через
> токены темы. Сначала перечисли компоненты, которые собираешься переиспользовать.

**Тесты:**
> Предложи тесты для формы по `spec.md`: рендер, клики, ввод, валидация, состояния,
> двойная отправка. Проверяй видимое поведение, не детали реализации.

## Что AI сделал хорошо

- Собрал цельный экран и все 5 состояний, не смешивая их.
- Реально использовал shadcn/ui: `Card`, `Input`, `Label`, `Alert`, `Badge`, `Table`.
- Вынес цвета и типографику в токены `src/styles.css` (oklch, `--ring`, `--success`).
- Добавил `<label htmlFor>` и `disabled` на время загрузки.
- Поднял каркас тестов: Vitest, jsdom, `@testing-library/react`, MSW.

## Что пришлось исправить после проверки

| # | Что сгенерировал AI | Почему плохо | Что сделали |
|---|---|---|---|
| 1 | `submit()` = `setTimeout(() => setState("success"), 1200)` | интерфейс не подключён к сервису | `src/lib/api.ts`: реальный `POST` в webhook, таймаут, `ApiError` |
| 2 | `ResultCard` всегда рисовал `SAMPLE_RESULT` | результат не зависит от ввода | данные берутся из ответа сервера |
| 3 | История — статичный массив `HISTORY` | не отражает работу пользователя | история пополняется результатами, дубли по `repo#issue` отсекаются |
| 4 | Валидации не было вообще | пустая форма уходила в запрос | `src/lib/validation.ts` + ошибки под полями, `aria-invalid`, `aria-describedby` |
| 5 | Не было guard от двойной отправки | два клика = два запроса | `inFlight` ref + тест со счётчиком запросов |
| 6 | Тесты проверяли маршрут и парсинг `?state=` | не проверяли поведение | 6 файлов поведенческих тестов, MSW-моки в формате реального API |
| 7 | В макете тип `question` | такого типа нет в API (там `bug/task/feature`) | заменили на `task`, поправили подзаголовок |
| 8 | В n8n Respond-нода отдавала `"{{ $json.validationError }}"` | выражение не вычислялось, 400 даже на валидном запросе | включили выражение в ноде, проверили `curl` → 200 |
| 9 | Один из тестов проходил при сломанной валидации | проверял сообщения, но не отсутствие запроса | добавили счётчик запросов + `expect(requests).toBe(0)` |
